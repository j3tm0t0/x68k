# harness/protprobe -- .x をウィンドウの中に閉じ込めるのに使える仕組みを調べる

OS/2 の DOS 窓のように、普通の .x をウィンドウの中で動かし、落ちても OS やほかのウィンドウを巻き込まないようにしたい。
68000 には MMU が無いので、X68000 のハードウェアにある保護の仕組みがどこまで使えるかを `protprobe.x` で確かめる。

```
make            # protprobe.x を作る (elf2x68k)
make test       # XEiJ (X68000 SUPER、68000、主記憶 12MB) で走らせる。最後の行が OK なら成功
```

実機では `protprobe.x > 結果.txt` と打つ。68000 でしか動かない (バスエラーのときにスタックに積まれる情報の形が 68010 以降と違う)。

## 調べること

1. ユーザーモードから各領域 (VRAM、I/O、SRAM、ROM、主記憶の下側) を読めるか
2. ユーザーモードからテキスト VRAM に書いたとき、バスエラーで止まって中身が変わらないか
3. 特権命令 `move to SR` が特権違反になり、スタックの PC が違反した命令を指すか。`move from SR` が通るか
4. スーパーバイザ領域設定 `$E86001` で主記憶の下側をスーパーバイザ専用にできるか。広げたまま DOS コール / IOCS コールが戻ってくるか
5. 増設メモリのスーパーバイザ領域設定 `$EAFF81`〜`$EAFF89` (2MB〜12MB を 256KB 単位でスーパーバイザ専用にする) があるか
6. ユーザーモードから守られた所 (`$002000` と `$FF0000`) へ `jsr (a1)` したとき、戻り番地を USP に積んでからバスエラーになるか、積む前になるか。
   フレーム 14 バイト、USP の前後、`[USP]` を出す。Z-OS の `prot_ti_fault` (常駐の TCP/IP の入口へ jsr したときのバスエラーを
   受ける所) は、フレームの PC の 2 / 4 バイト前が `jsr (An)` ならそこから戻り番地を決め、`[USP]` がそれと同じときだけ積んだとみなす。
   その判定が合うかも出す (合わなければ NG)。積んだ後でも前でも NG にはしない

例外は自前のハンドラで受けて記録し、試験の続きに戻る。PC が試験の関数の外にある例外は、元のハンドラへそのまま渡す。
4 で範囲を広げている間は割り込みを止める (IPL 7)。止めないと、OS が裏で動かしているユーザーモードのタスクがスーパーバイザ専用にした範囲に触れて落ちる (Z-OS で起きた。下の「Z-OS が落ちた件」)。
最後にベクタと `$E86001` を元の値に戻す。
`$EAFF81`〜`$EAFF89` は今の値を読み出せない (書き込み専用として扱う) ので、元の値には戻せない。試験で書いたポート (`$EAFF81` と、試したブロックのポート) は 0 (どこも守らない) のまま終わる。
ほかのプログラムがこのポートで増設メモリを守っていた場合、その設定は外れる。実機で走らせるときは、それを使うものが常駐していない状態で走らせる。
1 と 3 は、XEiJ と Z で確かめた結果 (下の表) を期待値にしている。違えば NG に数える。

## 結果 (2026-11-09)

| 項目 | XEiJ 0.26.10.08 (SUPER) | X68000 Z (Z-OS 0.1 の上) |
|---|---|---|
| 1. ユーザーモードで `$C00000` 以上と主記憶の下側を読む | すべてバスエラー | すべてバスエラー |
| 1. バスエラーで積まれる PC − 命令の番地 | 0 | 2 |
| 2. テキスト VRAM への書き込み | バスエラー、中身は変わらない | 同じ |
| 3. `move to SR` | 特権違反、PC は違反した命令 | 同じ |
| 3. `move from SR` | 通る (S ビットが見える) | 同じ |
| 4. 起動直後の `$E86001` の境界 | `$2E000` | `$4C000` |
| 4. 境界と書いた値の関係 | (値 + 1) × 8KB | **値 × 8KB** |
| 4. ワードで `$E86000` に書く | 反映される | **無視される** |
| 4. 範囲を広げて DOS `_GETDATE` / IOCS `_ONTIME` | 戻ってくる | 戻ってくる |
| 4. 最大の境界 | `$200000` (値 255、XEiJ のソースから。測っていない) | `$1FE000` (値 255、測った) |
| 5. `$EAFF81` | ある。256KB 単位で守れる | **無い (書くとバスエラー)** |
| 6. 守られた所へ `jsr (a1)` (2026-11-14 に追加) | 戻り番地を積んでからバスエラー。フレームの PC は飛び先 | まだ |

分かったこと:

- ユーザーモードの .x は、VRAM、I/O、SRAM、ROM に手を出せない (Z も同じ)。ウィンドウ内で動かすアプリからの `DOS _SUPER` / `IOCS _B_SUPER` を断れば、これらの領域には触れられない
- `$E86001` は Z でも使える。8KB 単位で、主記憶の 0 から最大 2MB 弱までをスーパーバイザ専用にできる。Human68k、ドライバ、ウィンドウシステムをこの範囲に置けば、アプリの暴走で書き潰されない
  - 同じ値を書いても、境界は XEiJ と Z で 8KB 違う。値を決め打ちせず、書いてからユーザーモードで読んで境界を測る (`protprobe.c` の `measure()`)
  - どちらが本物の X68000 と同じかは、実機 (XVI) では確かめていない
  - バイトで `$E86001` に書く。Z では `$E86000` にワードで書いても反映されない
- `$EAFF81` は Z に無い。プロセスごとに 256KB 単位で守る案は Z では使えない。Z ではアプリ同士のメモリは守れない
- 特権違反は 68000 でも命令からやり直せるので、割り込み禁止 (`ori #$700,sr` など) をウィンドウシステム側でまねできる。`move from SR` は 68000 では特権命令ではないので、アプリが読む S ビットは 0 のままで、スーパーバイザモードで動いているように見せかけることはできない
- バスエラーから命令を続けることはできない (68000 の制約)。違反したアプリは止めて片付ける
- バスエラーで積まれる PC は、命令の番地からずれる (68000 の資料では命令によって 2〜10 バイト先。XEiJ は 0、Z はこの試験では 2)。違反した命令を調べるときは PC ではなく、積まれたアクセス番地と命令 (IR) を使う

## Z-OS が落ちた件

最初の版は、範囲を広げている間も割り込みを止めず、例外はすべて自分で受けていた。
Z-OS の上で走らせると、2 回目の試験のあとで `zos: Illegal instruction (pc $197240)` と `zosh: Bus error (pc $BFFFBA)` が出て Z-OS が落ちた。
範囲を `$190000` まで広げている間に、Z-OS のユーザーモードのタスクがその範囲に触れてバスエラーになり、それを試験のハンドラが自分のものとして扱って試験の続きの番地へ戻したため、と見ている。
ウィンドウシステムを作るときも、`$E86001` を動かすならタスクの切り替えはウィンドウシステム自身が持つ必要がある。
