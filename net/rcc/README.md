# rcc: LAN の向こうの gcc で X68000 の C をコンパイルする

Z の上の gcc (真里子版 1.42) は遅い。`rcc.x` はソースを TCP で LAN の別の機械に送り、そこで elf2x68k の gcc 13 が
コンパイル・リンクした `.x` を受け取る。相手につながらないときは Z の gcc でコンパイルする。

| ファイル | 中身 |
|---|---|
| `rcc.x` (`rcc.c`) | Z で動かす。libsocket なので xip.x でも `tis.x -p` でも動く |
| `rccd.py` | 受ける側 (Linux / macOS、Python 3)。elf2x68k の `m68k-xelf-gcc` を呼ぶ |
| `tests/xeij_rcc.sh` | XEiJ + picosim (`tis.x -p`) での試験 |

## 使い方

受ける側 (elf2x68k の `m68k-xelf/bin` に PATH を通しておく):

```sh
python3 rccd.py --port 7790 --allow 192.168.1.0/24
```

Z:

```
set RCC_HOST=<受ける側の名前か番地>        (":ポート" も可。既定のポートは 7790)
rcc.x -O2 hello.c -o hello.x
```

- 送るもの: 引数のうち `.c` / `.s` / `.h` のファイルと、そのファイルと同じディレクトリの `*.h` 全部。名前はファイル名だけにして送る
- 引数はそのまま `m68k-xelf-gcc -m68000 -O2 ...` に渡す (`--cflags` で先に付けるものを変えられる)。`-o` が無ければ `a.x`
- gcc のメッセージは Z の標準エラーに出す。失敗したら `.x` を作らない。終了コードは gcc のもの
- つながらない (RCC_HOST が無い・相手が居ない・途中で切れた) とき: 環境変数 `RCC_LOCAL` (既定 `gcc.x %s -lgcc2`。`%s` に引数が入る)
  を `system()` で動かす。`RCC_LOCAL` を空にすると、Z ではコンパイルせずに 255 で終わる

## やり取り

1 回の接続で 1 回のコンパイル。受ける側は何も覚えない (ファイルは一時ディレクトリに置き、返したら消す)。
後で HTTP (AWS Lambda など) に替えるときは、同じ中身を本文で送ればよい。

```
Z → 受ける側:  RCC1\n
               ARG <バイト数>\n<引数>               (何回でも)
               FILE <バイト数> <名前>\n<中身>       (何回でも)
               END\n
受ける側 → Z:  RCC1 <終了コード> <ログのバイト数> <.x のバイト数>\n<gcc の出力><.x>
```

受ける側は `--allow` (既定 192.168.0.0/16 と 127.0.0.0/8) の外からの接続を断る。1 ファイル 4MB、合わせて 16MB まで。
gcc は `--timeout` 秒 (既定 120) で止める。

## 試験

```sh
net/rcc/tests/xeij_rcc.sh
```

XEiJ の Z で `tis.x -p` を上げ、Mac の `rccd.py` に `hello.c` (と同じディレクトリの `msg.h`) を送ってコンパイルし、できた `HELLO.X` を
Z で動かす。コンパイルのエラー、つながらないとき (`RCC_LOCAL` を動かす / 空なら何もしない) も見る。
