[前回のあらすじ]({{ site.baseurl }}{% post_url 2026-10-22-x68000z-diary-10 %}): X68000 Z から Linux に ssh して `uname -a` が返ってきた。1 回 65 秒、そのうち 59 秒が暗号。端末担当が作った VT100 をつなげば、対話シェルが動くはずだ。このシリーズでは、コードも調査もほぼ全部 AI (Claude) にやらせている。

## まず、シェルが動いた

ssh.x に VT100 をつないだ。出力は SSH のチャンネルから端末エミュレータへ、入力は X68000 のキーボードから SSH のチャンネルへ。`-t` を付けたときだけ端末になる。

`ssh.x -t moto@192.168.1.108` と打つと、65 秒の鍵交換のあとに Linux の bash のプロンプトが出た。

- `vi` で書いて `ZZ`、`less` でページ送り、`cat` で全画面スクロール。
- 上矢印で前のコマンド。Ctrl-C で `sleep` を止める。
- `ls --color` は、ディレクトリが青、プロンプトが緑。

VT100 はテキスト VRAM に直接描くので、シリアルのログには出ない。画面を VRAM から起こして確かめた。X68000 Z の画面に、Raspberry Pi の bash が出ている。

![Z の画面 (テキスト VRAM から起こしたもの)。Pi で ls --color -la /etc/ssh を打ち、exit したところ]({{ "/assets/z-ssh-ls-color.png" | relative_url }})

これで ssh は一区切り、のはずだった。

## ずるい思いつき

僕は画面を見ながら言った。「SCSI 経由で Pico の CPU 借りれたら、もっと速く計算できるよね」

Z の暗号が遅いのは、10MHz の 68000 だからだ。でも、その暗号のデータを SCSI 越しに運んでいる Pico (RP2040) は、133MHz が 2 つある。しかも普段は、ただ運ぶだけで暇だ。

ならやらせればいい。代理 ARP、代理 echo、ときて、今度は代理計算だ。USB モデムの NIC がホストの代わりに TCP を処理するのと同じ発想で、Z は「この鍵の掛け算をやって」と Pico に頼み、結果だけ受け取る。

ただし、ずるさには段階がある。僕らが決めたのはこうだ。

| Pico に出すもの | Pico に渡る秘密 | 速さ |
| --- | --- | --- |
| 何も出さない (既定) | なし | 65 秒 |
| ホスト鍵の検証だけ | **なし** (公開鍵と署名だけ) | 43 秒 |
| + 鍵交換 (X25519) | セッション鍵の素 | 19 秒 |
| + 認証の署名 | 自分の秘密鍵 | 12 秒 |

一番重いホスト鍵の検証 (26.7 秒) は、公開情報しか使わない。だから Pico に出しても安全性は 1 ミリも変わらない。これは「ずるくない」範囲だ。その先は、Pico を信頼する前提になる。もっとも、Pico は元から全パケットを運んでいるので、鍵を持たせれば中身まで読める、という違いでしかない。既定はオフにした。

## 代返の経路に相乗りする

要求と結果は、既にある netpipe の交換に混ぜた。新しい命令も別のセクタも足さない。レコードの先頭を `0xA5` にする。すると IP ヘッダのバージョン欄が「10」になるので、対応していない相手は「壊れた IP」として捨てて素通りする。IPv10 が来るまでは借りておく。

Z 側は npd.sys に命令を 5 つ (要求・問い合わせ・取り消し・応答・統計) 足し、計算を頼んで `_CHANGE_PR` で CPU を譲りながら待つ。Pico 側は Monocypher (小さくて素性のいい暗号ライブラリ) を載せ、交換が来たら専用のタスクで計算する。暇なときはタスクを眠らせておき、仕事が来たら起こす。

正しさは、いつもどおり Mac の Python を正として、RFC の固定ベクタと乱数で差分テストした。Z で動かす前に、全部ホストで通してある。

## 隣で、0.2 秒

試験プログラムを実機で走らせると、全部一致した。Pico の計算は、X25519 が 91 ミリ秒、ed25519 の検証が 150 ミリ秒、署名が 45 ミリ秒。Z から見た往復は 0.2 秒。改ざんした署名もちゃんと弾く。

そして ssh。

```
accel: ed25519 verify on the Pico in 149678 us (round trip 0.20 s)
Linux raspberrypi3 6.18.50+rpt-rpi-v8 ... aarch64 GNU/Linux
```

| ssh.x | 1 回のハンドシェイク |
| --- | --- |
| 素 (Z だけで計算) | 約 65 秒 |
| `-oAccel=verify` (検証だけ Pico) | 43 秒 |
| `-oAccel=kex` (+ 鍵交換) | 19 秒 |
| `-oAccel=all` (+ 署名) | **12 秒** |

12 秒のうち、暗号はもう 1 秒もない。残りは TCP の往復と、326KB のバイナリを B: から読む時間だ。もし Pico が応えなければ、Z は自分で計算に戻る。遅くはなっても、失敗はしない。

## いまのところ

X68000 Z から、色付きの Linux の対話シェルが動く。鍵交換は、隣の Pico に手伝わせれば 12 秒。ずるいけれど、Z にとって現実的なインターフェースは SCSI しかないのだから、ついでに計算も手伝ってもらうのは、悪くない。

次に何をやらせようか。xip.x を捨てて、TCP ごと Pico に預けてしまう日も、近い気がしている。言うのは簡単だ。
